# Casino Calendar - Logging Configuration Examples

# Environment Variables for Logging Configuration

# Set the log level (DEBUG, INFO, WARNING, ERROR, CRITICAL)
# Development: Use DEBUG for verbose output
# Production: Use INFO or WARNING for cleaner logs
LOG_LEVEL=INFO

# Optional: Enable file logging by setting a log file path
# If not set, logs will only appear in the console
# LOG_FILE=logs/casino_calendar.log

# Optional: Set the working directory for the application
# WORKING_DIR=/path/to/casino_calendar

# Example .env file content:
# Copy the lines below to a .env file in the project root

# For development (verbose logging)
# LOG_LEVEL=DEBUG
# LOG_FILE=logs/casino_calendar_dev.log

# For production (essential logs only)
# LOG_LEVEL=INFO
# LOG_FILE=logs/casino_calendar.log

# Usage examples:

# 1. Basic usage with default settings (INFO level, console only):
#    python app.py

# 2. Debug mode with file logging:
#    LOG_LEVEL=DEBUG LOG_FILE=debug.log python app.py

# 3. Production mode with file logging:
#    LOG_LEVEL=WARNING LOG_FILE=logs/production.log gunicorn app:server

# 4. Docker environment variables:
#    docker run -e LOG_LEVEL=INFO -e LOG_FILE=/app/logs/app.log casino-calendar

# JavaScript Console Logging:
# The browser console will show logs prefixed with [CasinoCalendar]
# Open browser dev tools (F12) -> Console tab to view client-side logs

# Log Format:
# Console: YYYY-MM-DD HH:MM:SS | LEVEL    | module_name          | message
# File:    YYYY-MM-DD HH:MM:SS | LEVEL    | module_name          | message

# Performance Logging:
# The system automatically logs performance metrics for key operations:
# - Data loading and processing times
# - Callback execution times
# - Modal generation performance

# Error Logging:
# All exceptions are automatically logged with full stack traces
